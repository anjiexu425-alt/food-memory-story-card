# 🍜 Food Memory Story Card（美食记忆故事卡）

> 把一张真实美食照片，变成一张可以在浏览器里**点击 3D 翻转**的数字手帐记忆卡。

正面是手帐风视觉（生成图 / 原图 / 内联插画）+ 6 张故事贴纸 + 3 个英文关键词，背面是一段**真实、不编造经历**的中文记忆故事（带日期、地点、一起吃的人、心情等可填写空位）。点击卡片任意位置即可翻转，像翻开一页手帐。

**面向任意宿主**：支持视觉理解 + 图像生成的多模态 AI（ChatGPT、豆包等）走完整主路径；纯文本 / 无生图能力的环境自动降级，且**绝不假装看过图或生成过图**。

## ✨ 项目特点

- 🎴 **手帐风正面**：3:2 横向构图，左侧大视觉 + 右侧 6 张贴纸，暖白纸纹、手撕边缘、轻微阴影，低饱和哑光质感
- 📖 **真实的背面记忆**：只写用户提供或照片可客观识别的信息；未提供的字段一律留空位，不编造日期、地点、同行人或经历
- 🔄 **3D 翻转交互**：纯 CSS 3D transform，点击任意位置翻转，再次点击翻回
- 🧭 **能力自动分流**：先探测「能否读图 / 能否生图 / 能否取到生成图」，自动走主路径或降级路径，任何降级都如实告知
- 🔒 **单文件自包含**：HTML + CSS + JS 全部内联，图片以 data URI / inline SVG 嵌入，无任何外部依赖，离线可用
- 📱 **全端适配**：手机、平板、电脑均可正常显示

## ⚙️ 能力分流

Skill 开始工作前先探测三项能力（**不写死任何工具名**，由宿主自行判断）：

| 能力开关 | 含义 |
| --- | --- |
| `can_read_images` | 能否理解图片内容（视觉理解） |
| `can_generate_images` | 能否生成图片 |
| `can_access_generated_image` | 能否拿到生成图片的可嵌入内容（文件路径 / base64） |

### 主路径（三项能力全部可用）

```
照片 → 视觉分析 → 生成手帐风正面图 → 获取生成图
     → 转 data URI 嵌入 HTML → 背面记忆故事 → 可翻转单文件 HTML
```

### 降级路径（自动切换，均如实告知）

| 触发场景 | 降级策略 | 禁止事项 |
| --- | --- | --- |
| 无视觉 | 明示无法读图，改用用户文字描述构建画面 | 假装看过照片、编造照片细节 |
| 无生图 | 有可读原图则用原图（转 data URI）；否则 inline SVG / CSS 手绘 | 引用不存在的图片或外部链接 |
| 生图成功但取不到文件 | 生成图单独交付 + HTML 用原图/SVG，明确告知 | 虚报「图片已嵌入」、假路径、假 base64 |

**诚实原则**：任何降级都会明确说明，绝不静默降级。

## 🔧 安装方法（任意宿主）

### ChatGPT / 多模态宿主（推荐先试）

ChatGPT 以 **Custom GPT** 方式使用：把 [`chatgpt-instructions.md`](./chatgpt-instructions.md) 中「Instructions」整段粘贴到自定义 GPT 的 Instructions 里，并**开启 Code Interpreter**（保证能读取生成图片转 base64 嵌入 HTML）。上传美食照片即可走完整主路径。

### 方式一：复制 SKILL.md（推荐）

```bash
git clone https://github.com/anjiexu425-alt/food-memory-story-card.git
cd food-memory-story-card
cp SKILL.md <你的宿主skills目录>/food-memory-story-card/
```

以 DeepSeek Harness 为例：

```bash
mkdir -p ~/.dsh/skills/food-memory-story-card

```

重启 / 刷新宿主会话，技能即可生效。之后说"帮我做一张美食故事卡"、给一个图片路径 / 链接，或用文字描述一道菜。

## 🎮 使用方法

1. 提供一张美食照片（本地路径 / 链接），或用文字描述一道菜；也可以直接说"给我做一张美食故事卡"；
2. 若你只说「做成手帐风格照片」，Skill 会**先出图**，然后**询问**你是否要把它做成可点击翻转的 HTML 记忆卡——确认后才生成 HTML；明确要卡片则直接生成，不询问；
2. Skill **先探测宿主能力**，按能力分流获取食物画面；
3. 识别主菜、情绪、核心视觉锚点；
4. 生成**正面插画描述**（暖白纸、哑光水粉 / 剪纸感、低饱和、温暖怀旧）；
5. 挑选正好 **6 个故事向贴纸元素** + **3 个英文关键词**；
6. 撰写背面**中文记忆文案**（只写真实信息，未提供的日期 / 地点 / 同行人 / 心情留空位）；
7. 按能力生成正面视觉（生图 → data URI；否则原图 / inline SVG），输出**可点击翻转的单文件 HTML**；
8. 保存为 `美食记忆故事卡.html`，用浏览器打开即可点击翻转。

## 🛠 技术细节

- 纯前端：`HTML + CSS + JS`，无任何依赖；测试零第三方依赖
- 翻转交互：CSS `transform-style: preserve-3d` + `rotateY(180deg)`
- 图片嵌入：data URI（`data:image/...;base64`）或 inline SVG，完全离线可用
- 响应式：`clamp()` / 百分比 + `@media` 适配移动端

## 🚦 V1 Beta 状态

当前为 **V1 Beta**：核心链路（能力探测 → 图片嵌入 → fallback → 单文件 HTML）已实现并有测试覆盖，可在 ChatGPT / 豆包等具备视觉 + 生图能力的宿主直接使用。已知限制见下。

### 宿主能力限制（Skill 本身无法解决）

- **视觉 / 生图 / 取图能力由宿主提供**：Skill 只能探测和分流，无法给宿主安装视觉或图像生成能力；无视觉宿主只能走文字描述 + SVG/原图路径。
- **取不到生成图片文件**时只能分开交付（图片与 HTML 是两个文件），无法在单文件内嵌；这取决于宿主的生成工具是否暴露可访问产物。
- **超大图片**（数 MB 级）转 base64 后 HTML 体积会很大，属预期行为，建议宿主先压缩或提示用户。
- 不同宿主对「图片上传」的入口不同（粘贴、拖拽、本地路径），Skill 只约定输入信息，实际取图方式由宿主决定。
